# 第 3 阶段：接入 DeepSeek，同时保留事实边界

## 为什么不是让模型接管全部流程

简历解析、技能命中、原文证据和基础评分继续由确定性代码完成。DeepSeek 只负责更适合生成模型的任务：表达优化、自我介绍、面试问题和基于上下文的问答。这样即使模型超时或不可用，离线报告仍然能返回。

## 数据流

```text
简历 → 本地解析与脱敏 → 用户勾选授权 → DeepSeek Responses API
                                      ↓
规则报告 ← 技能/年限事实检查 ← 结构化生成结果
```

## 安全措施

- API Key 只读取 `DEEPSEEK_API_KEY` 环境变量。
- 默认不调用外部模型，页面必须主动勾选。
- 发送前遮蔽手机号、邮箱和微信号。
- 模型输出使用 Pydantic 校验结构。
- 自我介绍中新出现的技能和年限会被标记为待核验。
- 超时、限流、连接失败不会破坏离线分析结果。

## 面试表达

“我将确定性分析与生成式能力分层：本地代码负责证据、评分和隐私脱敏，DeepSeek 负责表达与问答。模型输出必须通过结构校验和事实检查，并设计了超时、重试和离线降级，因此不是一次裸 API 调用。”
